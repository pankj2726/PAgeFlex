## TASKS-02

| # | Decision | Reason |

| D14 | **Task 1 root cause (identified from source, NOT reproduced in a browser).** In `@cantoo/pdf-lib`, `PDFDocument.removePage()` also calls `context.delete(page.ref)` (PDFDocument.js:703-713), so my export's "remove every page, then re-add in the new order" produced page objects that no longer existed → a broken or empty PDF, for every export, not only edited ones. Fixed in the previous change by re-assigning each page object under its ref before `addPage`; covered by `export-robustness.test.ts` (including a 60-page nested tree reduced to one page). Hypothesis audit: **a** real gap (no validation, failures only `console.warn`) → `invalidReason()` + warnings returned to the UI; **b** already handled (`safeText`, raster fallback); **c** not an issue (payload is structured-cloned; results are transferred out) – added a zero-length guard and de-duplicated the transfer list; **d** real gap (no timeout / `onmessageerror` / clone failure handling) → idle timeout + typed `JobError`; **e** real gap → 60 s revoke, fallback link, optional Save-as; **f** already true (`PDFDocument.load` from `sourceBytes` on every export); **g** order is fixed in code and asserted by test. |
| D15 | Glyph map in page space with estimated per-glyph advances (pdf.js 5.x here has no per-glyph output). Hit-testing uses the glyph's own frame (equivalent to point-in-oriented-quad for rectangles); the ≤ 2 pt tolerance applies ALONG the baseline only, never vertically, so inter-line gaps capture nothing. Quad = 0.8 em ascent + 0.2 em descent; cover boxes use tight ink extents (x-height/cap-height). Columns: segments split on gaps > 1.6 em; page-wide segments form bands; a new column starts when overlap with the previous line < 30%. |
| D16 | Edit objects carry `covers[]` (one tight rectangle per target line, clipped away from non-target glyphs) instead of a padded line box. Created ONLY by `makeEditObject` (guards 1–3) for both click-to-edit and Replace. |
| D17 | Post-edit verification compares character multisets and tolerates the covered-but-present original (KL-EDIT-2); failing pages are rolled back by re-export. Auto-rollback is applied at download time, not at edit time (the PDF is only built then). |
| D-FR-1 | Word characters are `\p{L}\p{N}\p{M}_`. `don't` and `well-known` are single words. **One exception, to satisfy the §3.5 row `cat's`:** a trailing possessive/contraction `'s` / `’s` ends the word, so `cat` (whole word) matches in `cat's` but not in `concatenate`. (§3.2 and the §3.5 table conflict on this; this is the only rule that satisfies both.) |
| D-FR-2 | Boundaries are decided in code, not with `\b` and not with regex lookarounds (spec §3.2 suggests lookarounds): code can honour the apostrophe rule, defer to `Intl.Segmenter` for CJK/Thai, and a rejected candidate can retry at `index+1` so it never hides an overlapping valid match. Same Unicode-aware class, same behaviour. |
| D-FR-3 | "Exact phrase / word order" defaults to ON (a literal multi-word query is a phrase; turning it off searches each word separately). Whitespace in a query matches any whitespace run, including a line break. |
| D-FR-4 | Hyphenation: a line-final hyphen after a letter is dropped from the index only if the next line starts with a lowercase letter. A genuine compound broken at a hyphen ("well-⏎known") therefore indexes as "wellknown". Columns are separated by a control character so a phrase never spans two columns. |
| D-FR-5 | Regex mode runs the complete search in `search.worker.ts`, terminated after 4 s; literal queries are escaped and run on the main thread. NOTE: while debugging, `build_project` timed out four times; I first suspected this third inline worker and temporarily replaced it with a Blob worker. That was wrong – the build passed as soon as the real cause (edits lost to a race, below) was repaired, and the worker was restored. |
| D19 | **Rebrand to PageFlex.** Name, tagline and description are single constants in `src/lib/config.ts`; every title, heading, meta tag, JSON-LD block and static page reads them. The hero heading is built by splitting the ONE tagline string around the highlighted phrase "adapt PDFs", so the spaces in "Edit, merge, and adapt PDFs instantly." cannot be lost to a JSX line break. Internal identifiers: IndexedDB renamed `quillfold` → `pageflex` (no released users, so no migration); the `qf-` localStorage prefix is kept (an abbreviation, not the old name). The user wrote "PAgeFlex"; read as a capitalisation slip → "PageFlex". |
| D20 | **Theme.** Colours come from Anthropic's Claude palette: Crail `#C15F3C` (primary), Clay `#D97757` (accent), Pampas `#F4F3EE` / Ivory `#FAF9F5` (surfaces), Oat `#E8E6DC`, Cloudy `#B1ADA1`, Slate `#141413` (ink), Manilla `#EBDBBC`. Instead of editing hundreds of class names, the Tailwind `indigo-*` and `slate-*` scales are remapped in `@theme` (`src/index.css`); dark mode uses the same scales. SVG editing layers carry hard-coded indigo presentation attributes, re-coloured by attribute selectors in CSS (the "accent bridge") because CSS beats presentation attributes. These are Anthropic's brand colours used as inspiration for a colour scheme; the PageFlex logo, name and copy are original. |
| D21 | **Monospace UI with system fonts only.** `--font-sans` and `--font-mono` are both a monospace stack (JetBrains Mono → SF Mono → Cascadia/Roboto Mono/Menlo/Consolas → monospace). No font files are bundled: JetBrains Mono is SIL OFL-1.1, which is outside the blueprint's permitted licence list (C4) and would fail `scripts/license-check.mjs`, and a CDN font would add a third-party request. Users who have JetBrains Mono installed get it; everyone else gets their platform's monospace. Root font size is 15 px because monospace is wider than proportional type. PDF page content and the document-text previews inside the editor canvas keep the PDF's own font mapping (that is document content, not UI). |
| D22 | **Animation feedback** (all CSS, no animation library, all disabled by `prefers-reduced-motion`): staggered fade-up on the hero and tool cards, floating logo/upload icon, pulsing drop-zone ring with scale on drag-over, pop-in dialogs/toasts/errors, sliding toasts and find panel, shimmering progress stripes with live %, press (scale) and hover-lift feedback on every button, self-drawing success tick after export / tool completion, fade-in of rendered page canvases, hover lift on page thumbnails, drifting colour blobs behind the hero. |
